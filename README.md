# 华为路由器 IPv6 防火墙白名单 · 动态同步

NAS 上跑一个容器，**盯着自己的 IPv6 地址**。地址一变，就自动把华为路由器
`/api/ntwk/ip6firewall_trustlist`（IPv6 防火墙白名单）里对应的那条规则原地更新。

典型场景：家里是电信/联通/移动的 IPv6，运营商**定期重拨换前缀**（甚至设备接口标识也一起变）。
以前每次变了都要登路由器手工改白名单，现在容器自己搞定。

- 纯 Python 标准库，**零 pip 依赖**，镜像基于 `python:3.12-alpine` 约 60 MB
- 默认 **60 秒**轮询，地址没变**不发任何写请求**（不折腾路由器 flash）
- 按条目名 upsert：**存在则改、不存在则加**，不会把 32 个名额越占越满
- 写完**回读核对**，设备"假装成功"也能被发现
- 密码错误**指数退避**（最长 6 小时）—— 设备只允许连错 3 次，绝不快速重试锁死账号
- 自带**浏览器控制台**：看状态、改设置（路由器地址/密码/检测周期…），改完即生效

## 快速开始

```bash
# 1. 在 docker-compose.yml 的 environment 里改控制台登录账号
#      - ADMIN_USERNAME=admin
#      - ADMIN_PASSWORD=你的口令

# 2. docker compose build && docker compose up -d
#    浏览器打开 http://<本机IP>:6600/ 登录控制台

# 3. 在网页「路由器连接」里填 路由器地址 / 管理员密码，保存即开始同步
#    其余设置（NAS 的 MAC、检测周期等）也全在网页里改，改完热生效
```

查 NAS 自己的 MAC：控制台点「刷新设备列表」，或
`docker compose run --rm ipv6sync --list-hosts`。

看一眼是否生效：

```bash
docker compose run --rm ipv6sync --whitelist   # 当前白名单
curl -s localhost:8099/state | python -m json.tool   # 运行状态
curl -s -o /dev/null -w '%{http_code}\n' localhost:8099/healthz   # 200 = 正常
```

## 浏览器控制台（可选）

在 compose 的 `environment:` 里设了 `ADMIN_PASSWORD` 就自动开启；
**不填则不监听这个端口**（安全默认）。

```
http://<NAS 的 IP>:6600/      用 ADMIN_USERNAME / ADMIN_PASSWORD 登录
                              端口可用 compose 的 - PORT=xxxx 改，0 = 关闭
```

能做的事：

| 区域 | 内容 |
|---|---|
| 状态条 | 同步是否正常、路由器是否已登录、IPv6 防火墙开关、最近一轮时间、累计写入次数 |
| 快捷操作 | 立即同步一次 / 测试连接 / 重置累计写入 / **IPv6 防火墙总开关**（滑动开关；关闭后白名单整体不生效、同步暂停，直到重新打开）（执行结果统一在「运行状态」页的「操作结果」栏查看） |
| 路由器ipv6白名单 | 路由器同款表格展示当前条目；点「＋ 添加」**选设备**写入白名单并加入自动维护（地址变化原地更新）；可编辑/删除。总开关关闭时整卡收起为一行提示 |
| 设置表单 | 路由器地址与账号密码、检测周期、演练模式…… 改完点「保存并应用」**即时生效**；白名单条目在白名单卡里按设备管理 |
| 设备列表 | 在线 / 离线 / 黑名单 / 儿童上网 四页签；白名单弹窗的设备下拉就来自这里 |
| 同步记录 | 白名单每次真实改动的流水（新增/更新/删除/开关），支持搜索与动作筛选；落盘 `/data/events.jsonl` 重启不丢，保留上限页内可调 |
| 通知设置 | ntfy / gotify / 企业微信群机器人三渠道独立开关，可同时启用、同时推送；标题可自定义（三渠道共用，默认「IPv6 白名单已更新」）；防火墙白名单每次被修改后自动推送变更；可发测试通知验证配置 |
| 界面主题 | 右上角按钮在「跟随系统 / 深色 / 浅色」间循环切换，选择记忆在浏览器本地 |

### 没有 Docker 也想先看一眼界面？

控制台是纯标准库 HTTP 服务，可以脱离容器直接跑（**对真实路由器零影响**）：

```bash
python preview_console.py                      # http://127.0.0.1:8090/  admin / preview
PREVIEW_PORT=9000 PREVIEW_PASSWORD=xxx python preview_console.py
```

它把路由器地址指向 `192.0.2.1`（RFC 5737 的 TEST-NET-1，永远不可达），
会话与设置文件写到系统临时目录 —— 所以**不会碰真实设备、不会消耗登录失败次数、
不会污染 `/data`**。设备类按钮（同步、读白名单）会失败，这是预期的：
这个脚本只是让你看界面和表单行为。

`preview_console.py` 只是开发辅助，**不会被打进镜像**（镜像只 `COPY app/`）。

### 为什么要有这个页面

容器里的环境变量**只在创建容器时注入一次**，改 `.env` 得 `up -d --force-recreate`
重建容器。而"路由器 IP 填错了想改一下"这种事儿不该要求重建容器 —— 所以可变的字段
放在 `/data/settings.json` 里，由网页维护，优先级是：

```
网页设置（/data/settings.json）  >  .env / docker -e  >  代码默认值
```

每个字段旁边有来源标记（`网页设置` / `默认值`），一眼能看出当前值是谁给的。
表单里**只有改动过的字段**会被提交，其余保持原样。

### 安全说明（这一块请认真看）

- 页面能改路由器密码，等于**一部分路由器管理权**。不要做端口映射到公网，别用弱口令。
- 登录防爆破，三层：单 IP 5 分钟内错 8 次 → 锁定，**反复触发锁定逐次翻倍**
  （5 分钟 → 10 分钟 → …，上限 6 小时）；所有来源合计 5 分钟内错 60 次 →
  全局熔断一个窗口（防换 IP 分摊）；每次登录校验前恒定延时 0.25 秒。
  锁定期内**密码对也不放行**；登录成功即全部清零。触发时日志有记录（`docker logs`）。
- `Origin` 与 `Host` 不一致的 POST 直接 403，且只接受 `application/json`
  —— 跨站表单发不出这个 Content-Type，配合 `SameSite=Lax` 挡掉 CSRF。
- 会话令牌只存内存（重启即失效），Cookie 带 `HttpOnly` + `SameSite=Lax`，默认 12 小时过期；
  登录时勾选「保持登录(7天)」则按 7 天有效期签发（浏览器不保存密码明文）。
- **在网页里填的路由器密码会明文写进 `/data/settings.json`（权限 0600）**，
  和放在 `.env` 里是同一个安全等级。不想落盘明文就用 `ROUTER_PASSWORD_FILE` 指向的
  Docker secret；想彻底不落盘，就只提供会话文件（见下）。
- 不在局域网里、或者不想开这个口子：`PORT=0` 或直接不设 `ADMIN_PASSWORD`。

## 怎么把路由器地址与账号交给容器

**推荐：全部在网页里填。** 容器启动后打开控制台，在「路由器连接」里填
路由器地址与管理员密码，保存即生效（写入 `/data/settings.json`，优先级
高于环境变量，无需重建容器）。没填密码时容器只是待机，不会去碰路由器。

环境变量仍可用（进阶：Docker secret、批量部署等），优先级低于网页设置：

| 变量 | 默认 | 说明 |
|---|---|---|
| `ROUTER_HOST` | `192.168.3.1` | 路由器管理地址；换了 LAN 网段就改 |
| `ROUTER_USER` | `admin` | 管理员用户名；华为家用路由固定是 `admin` |
| `ROUTER_PASSWORD` | — | 直接给值（`.env` / `docker -e`） |
| `ROUTER_PASSWORD_FILE` | — | 从文件读密码（Docker secret）；与上一项二选一 |

`docker compose` 里是 `env_file: .env` 这一行在起作用：容器启动时把 `.env` 里的变量
塞进进程环境，程序用 `os.environ` 读。**改完 `.env` 必须重建容器**
（`docker compose up -d --force-recreate`）才生效 —— 单纯 `restart` 不会重新读。

密码三种给法（按安全性递增）：

1. 明文写在 `.env` 里（最简单，`chmod 600 .env`）
2. `ROUTER_PASSWORD_FILE=/run/secrets/router_password` + compose 的 `secrets:`（见离线 compose 注释）
3. **不给密码，只复用会话**：把一份有效的 `session.json` 放到 `/data/` 里，
   程序启动时先试复用。会话过期后就没法重登了（日志会一直提示），
   所以这条路只适合"临时先跑起来"。

> 网页里改的设置（含路由器密码）存在 `/data/settings.json`，优先级**高于** `.env`。
> 也就是说：用网页改过密码之后，再改 `.env` 里的 `ROUTER_PASSWORD` 是不生效的
> —— 得在网页上改，或者删掉那个文件里对应的键。

## 工作原理

```
        ┌──────────────────────── NAS（宿主机） ────────────────────────┐
        │                                                             │
        │   IPv6: 240e:3a4:48ff:6d10:7173:1ffc:64ed:82c0               │
        │              │                                              │
        │              │ ① 发现                                     │
        │   ┌──────────▼───────────────────────────┐                  │
        │   │  ipv6sync 容器（必须 host 网络）      │                  │
        │   │  读 /proc/net/if_inet6               │                  │
        │   │  → 本机全部全局 IPv6                 │                  │
        │   │    （跳过 tentative / deprecated）   │                  │
        │   └──────────┬───────────────────────────┘                  │
        └──────────────┼──────────────────────────────────────────────┘
                       │ ② 与白名单里的 LocalIp 比对
                       │ ③ 有变化才写（create / update / delete）
              ┌────────▼─────────┐
              │  华为路由器       │  /api/ntwk/ip6firewall_trustlist
              │  192.168.3.1      │  /api/ntwk/ip6firewall_enable
              └──────────────────┘
```

### 取址：只读本机网卡（**一条路，没有开关**）

每 `POLL_INTERVAL` 秒读一次本机网络接口上的全局 IPv6，与白名单里本程序维护的
条目比对，**有变化才写** —— 没变化就一个字节都不碰设备（写入是 flash 操作）。

**为什么不用路由器那张设备表**（`GET /system/HostInfo`）：它本质是**邻居表缓存** ——
更新有延迟（几秒到一分钟），而且设备换了地址之后它还会留着已经不用了的旧地址。
而本机网卡上的地址才是**报文真正能落地的地方**，是唯一的地面真值。

代价是**容器必须用 `network_mode: host`**：只有这样才看得到 NAS 自己的网卡。
bridge 模式下容器有独立网络命名空间，读到的是**容器自己**的地址，与本机无关 ——
那时程序会因为「没发现地址」跳过这一轮（状态里写明原因），**不会瞎写一条上去**。

> 早先版本有 `SOURCE` / `MISMATCH_POLICY` 这类"问谁"的选项，还有 `auto`
> 两边取交集的逻辑。实际用下来只有"读本机网卡"这一条是准的，其余都是让人
> 犹豫的岔路，已经全部去掉。

### 网卡上有几个地址就写几条（未绑 MAC 的老规则）

> 1.0.8 起白名单规则默认「按设备」取路由器第一条地址（见上一节）。本节描述的是
> 未绑定 MAC 的环境变量老规则 —— 它们仍读本机网卡，行为与旧版完全一致。

**这是最容易踩的坑**：NAS 这类 Linux 设备常常同时有多个全局 IPv6 ——
SLAAC 稳定地址、RFC 4941 隐私临时地址、DHCPv6 分配地址，前缀一样、只有后 64 位不同。
而白名单的 `LocalIp` 是**目的地址匹配规则**：一个报文要命中它，目的地址必须真的
落在这台设备的网卡上。**只写一条就是赌固件给的顺序**，赌错了就变成
"地址明明加进白名单了，却怎么也连不通"，而且在路由器页面上看不出区别。

所以**网卡上有几个就写几条**，条目名依次是 `NAS`、`NAS@2`、`NAS@3`
（多端口时再拼 `-端口`，如 `NAS@2-5005`）。第一个地址沿用基础名 `NAS`，
升级时不占新名额，旧版本留下的那条会被原地更新。

隐私临时地址排在最后（它过期就换，不适合当基础条目名 `NAS`），但**照样会写** ——
报文完全可能落在它上面。带 `tentative`（DAD 未完成）或 `deprecated`（即将弃用）
标志的地址会被跳过：这两种此刻写进去没有意义。

名额方面：白名单一共只有 **32 个位置**，占用 = 地址数 × 端口数。超出预算的地址
会被截断并在状态里明确告警，**你自己手工加的条目永远不会被挤掉**。

设备地址减少（旧地址过期）时，对应的条目会被**自动删除**，不会越积越多；
只有名字看起来是本程序生成的那些会被动，`别的设备-22` 这类手工条目一个都不碰。

### 按设备放行别的机器（白名单页「＋ 添加条目」）

1.0.8 起白名单规则绑定**设备**而不是"本机"：在白名单卡里点「＋ 添加条目」，
从设备列表选一台设备（自动填入它在路由器设备表里的第一条地址），保存后这条
规则就交给程序自动维护 —— 设备地址一变，白名单条目原地更新。

绑定设备的规则取址走**路由器设备表（HostInfo）第一条**：华为的排序是
「最新出现优先」，第一条就是该设备现役的地址，也是路由器自己选设备时会填的
那条。三个保护：

- **设备离线** → 本轮跳过，白名单保持不动（不删不写）；
- **路由器表里没有该 MAC / 表为空**（路由器刚重启还没重建）→ 本轮跳过，
  绝不会误判成"没地址"而清掉条目；
- **规则指向本机（NAS 自己）** → 再用 `/proc` 的 flags 做一次幽灵校验，
  路由器残留的旧地址绝不写入。

表格里带「自动维护」徽标的条目由程序管理；「手工」条目程序一个字节都不碰，
编辑/删除直接作用于路由器。**删除自动维护条目会连同维护规则一起删** ——
否则下一轮又会被写回来。

## 配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `ROUTER_HOST` | `192.168.3.1` | 路由器地址 |
| `ROUTER_USER` | `admin` | 管理员用户名 |
| `ROUTER_PASSWORD` | — | 管理员密码（或下面的 `_FILE`） |
| `ROUTER_PASSWORD_FILE` | — | 从文件读路由器密码（Docker secret） |
| `ENTRY_NAME` | `NAS` | 白名单条目名（旧版 env 方式，读取时自动迁移成网页规则列表；推荐改用控制台白名单页按设备添加） |
| `ENTRY_PORT` | `-1` | 放行端口；`-1` 或留空 = 全部端口；多个用英文逗号分隔（如 `16667,5005`，每端口一条条目） |
| `REMOTE_IP` | `::/0` | 允许来源，默认不限制 |
| `TARGET_MAC` | — | 目标设备 MAC；填了这条规则就改为「按设备」跟随路由器设备表维护，不填则读本机网卡 |
| `POLL_INTERVAL` | `60` | 轮询间隔（秒） |
| `ENSURE_FIREWALL_ON` | `false` | IPv6 防火墙总开关若关着，是否自动打开 |
| `VERIFY_AFTER_WRITE` | `true` | 写后回读核对 |
| `DRY_RUN` | `false` | 只打印不写路由器 |
| `ONCE` | `false` | 跑一轮就退出 |
| `LOGIN_BACKOFF_BASE` / `MAX` | `300` / `21600` | 密码错后的退避起点/上限（秒） |
| `HEALTH_PORT` | `8099` | 健康检查端口（`0` 关闭） |
| `LOG_LEVEL` / `LOG_JSON` | `INFO` / `false` | 日志级别 / JSON 日志 |
| `SESSION_FILE` | `/data/session.json` | 会话缓存（**只存 Cookie 和 CSRF 令牌，不含密码**） |
| `ADMIN_USERNAME` | `admin` | 控制台登录用户名（compose 的 environment） |
| `ADMIN_PASSWORD` | — | 控制台登录密码；**不设就不启动控制台** |
| `ADMIN_PASSWORD_FILE` | — | 从文件读控制台密码 |
| `PORT` / `WEB_HOST` | `6600` / `0.0.0.0` | 控制台监听端口；`PORT=0` 关闭 |
| `WEB_SESSION_TTL` | `43200` | 控制台登录有效期（秒） |
| `SETTINGS_FILE` | `/data/settings.json` | 网页保存的设置（优先级高于环境变量） |

上表中除 `LOGIN_BACKOFF_*`、`SESSION_FILE`、`RULES*` 之外的字段都能在**控制台页面**上直接改。

### 一台路由器管多台设备

用 `RULES` 传 JSON 数组，每条规则各自认领一个条目：

```env
RULES=[{"name":"NAS","port":16669,"mac":"00:11:22:AA:BB:CC"},
       {"name":"NVR","port":"all","mac":"AA:BB:CC:DD:EE:FF"},
       {"name":"HomeAssistant","port":8123}]
```

## NAS 上怎么部署

### 群晖 DSM（Container Manager / Docker）

1. 把 `ipv6sync` 目录传到 NAS，例如 `/volume1/docker/ipv6sync`
2. Container Manager → **项目** → 新增，路径选到该目录（会读取 `docker-compose.yml`）
3. 或直接 SSH：
   ```bash
   cd /volume1/docker/ipv6sync
   cp .env.example .env && vi .env
   sudo docker compose up -d --build
   ```
4. **必须用 `network_mode: host`**（群晖 DSM 7 起支持）——这是读到 NAS 真实 IPv6 的前提，换成 bridge 只会读到容器自己的网卡

### 威联通 QNAP（Container Station）

同理，用"应用程序"导入 `docker-compose.yml`。注意 QNAP 的默认网关同样是路由器，
容器能直接访问 `192.168.3.1`。**同样必须 host 网络** —— 不支持的话程序读不到 NAS
自己的网卡，会一直跳过并在状态里写明原因。

### 群晖 Container Manager 里找不到 host 网络选项？

用命令行 `docker compose up -d`（GUI 对 host 网络的支持不完整）。

**本程序需要 host 网络**才能读到 NAS 自己的网卡。bridge 下读到的是**容器自己**
的地址，与本机无关 —— 那时程序会一直停在「没有发现地址」，而不是瞎写一条上去。

### 离线部署：NAS 上没有外网 / 不想在 NAS 上构建

仓库里附了**手工组装好的镜像 tar**（本机没有 Docker 引擎，所以不是 `docker build`
出的，而是按 docker-save 格式拼的，已逐层校验过）：

```
ipv6sync/offline/dist/
├── ipv6sync-1.0.8-amd64-image.tar     51.4 MB   x86_64 NAS（唯一产物）
├── docker-compose.offline.yml          无 build 段的 compose
├── .env.example                        环境变量模板
├── SHA256SUMS.txt                      tar 的 sha256
└── README.md                           离线部署与排错说明
```

## 安全说明

- 密码只用在**本地算 SCRAM 挑战响应**，服务端只存派生值；日志里从不打印密码
- 登录时**校验服务端签名**，对不上立即中止（防中间人 / 防连错设备）
- `session.json` 里只有会话 Cookie 与 CSRF 令牌，权限 `0600`，原子写
- `.env` 含明文密码：`chmod 600 .env`，别提交到公开仓库（`.gitignore` 已排除）
- **在控制台网页里填的路由器密码会明文写进 `/data/settings.json`（权限 0600）**
  —— 与 `.env` 同等级；不想落盘就用 `ROUTER_PASSWORD_FILE`
- 更稳妥的做法是用 Docker secret 或 NAS 自带的凭据管理把密码注入
- 控制台默认**不启动**（没配 `ADMIN_PASSWORD` 就不开端口），且**不要**把它暴露到公网

### 为什么退避这么久

设备对登录失败的限制是 **3 次**（可以从登录响应里的 `maxfailtimes` 读到）。
所以本程序**不做自动重试密码**：错一次就按 5 分钟 → 10 → 20 …… 最长 6 小时退避。
如果你看到 `登录失败（第 1 次）……已退避 300 秒`，**先人工确认密码**再继续。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| `未发现可用 IPv6` | 容器不是 host 网络（读到的是容器自己的网卡），或这台机器确实没有全局 IPv6 |
| `接口返回 404 空响应` | 会话失效（设备用 404 藏受限路径）。程序会自动重登；反复出现说明密码不对 |
| `CSRF 校验失败 … 需要重新登录` | 会话被设备注销。删掉 `data/session.json` 让它重登 |
| `白名单已满（32 条）` | 先去路由器页面清理无用条目 |
| `写后回读不一致` | 设备没真保存。检查 **IPv6 防火墙总开关是不是关着**（关着时条目可能写不进去） |
| `IPv6 防火墙当前是关闭的，白名单不会生效` | 符合预期。要自动打开就设 `ENSURE_FIREWALL_ON=true` |
| 容器的地址是 `172.x` 开头 | 用了 bridge 网络，读到的是容器自己。改成 `network_mode: host` —— 本程序只有这一种部署方式 |
| **地址加进白名单了却连不通** | 网卡上还有别的全局 IPv6 没写进去（只写一条就是赌固件给的顺序）。升到 ≥ 1.0.2（本版默认全部写入）；在网页「路由器 ipv6 白名单」栏点「读取白名单」，看 `NAS` / `NAS@2` 各自的内网 IPv6（「归属规则」列能分辨哪些是程序写的）；「运行状态」页的 JSON 里 `status.rules.NAS.addrs` 是本轮实际写入的全部地址 |
| 白名单里只有 1 条程序维护的条目（没有 `NAS@2`） | 这台机器确实只有一个全局地址，或白名单名额被占满了（见下一行） |
| 状态里提示「名额只剩…只写前 N 个地址」 | 白名单 32 条被占满了。精简端口或清理手工条目 |
| 6600 打不开 | 没设 `ADMIN_PASSWORD`（日志里有明确提示），或忘了 `up -d --force-recreate`；bridge 网络时检查 `ports:` 映射 |
| 网页改了设置不生效 | 改的是 `.env` 还是网页？**网页设置优先级更高**，网页改过之后 `.env` 就不起作用了 |
| 网页登录提示「失败次数过多」 | 5 分钟内错了 8 次触发锁定（防爆破）。等一会儿再试；反复触发锁定会逐次变长（上限 6 小时） |
| **一直显示「同步 等待首轮」，但白名单里明明有它写的条目** | 1.0.2 及更早的显示 bug：网页是轮询取状态的，拿到的 `ok` 恒为空，于是一直说「等待首轮」。升级到 ≥ 1.0.3；现在这格会显示「正常」、鼠标悬停能看到最近一轮成功的时间 |
| **「累计写入」停在很小的数，重启后归 0** | 1.0.2 及更早只在内存里计数，容器一重启就归零。≥ 1.0.3 把计数存进 `data/state.json`（挂载卷里），重启不清零；同一格悬停能看到「本次启动以来 N 次」，两者对照就能判断到底是在写还是刚重启过 |
| 状态里出现「计数文件异常 统计不可信」 | `data/state.json` 读不出来或写不进去（多半是挂载目录属主不对，见上面的 `chown 10001:10001`）。同步本身不受影响，只是数字不可信 |
| 启动失败提示 `ROUTER_PASSWORD` | 只在 `--once` 单次模式出现。常驻模式没密码会待机等你在网页里填 |

调试用：

```bash
docker compose run --rm -e LOG_LEVEL=DEBUG -e DRY_RUN=true ipv6sync --once
```

## 协议备忘（逆向自设备固件）

这些细节都是实机验证过的，改代码时别踩回去：

1. **登录是 SCRAM-SHA256，不是表单提交**
   `POST /api/system/user_login_nonce {username, firstnonce}`
   → 本地 `PBKDF2(password, salt, iterations)` → `clientproof`
   → `POST /api/system/user_login_proof {clientproof, finalnonce}`
   登录成功后校验 `serversignature`。

2. **HMAC 的参数顺序是反的**（固件里就不是 RFC 5802 的写法）：
   `hmac_sha2(key, message)` 内部是 `HMAC(key=message, data=unhexlify(key))`。

3. **CSRF 令牌每次响应都轮换**，POST body 内嵌
   `{"data": {...}, "csrf": {"csrf_param": "...", "csrf_token": "..."}}`。
   令牌一变**必须立刻落盘** —— 漏掉就会让下一个进程拿旧令牌，
   设备回 `Menu.csrf_err` 并**直接注销整个会话**（表现为所有鉴权接口变 404 空响应，
   而 `deviceinfo` 这类免登录接口照样 200，极具误导性）。

4. **增删改的报文形态**：
   ```
   create : {"action":"create", "data":{"Name","RemoteIp","LocalIp","Port","ID":""},  "csrf":{...}}
   update : 同上，ID 为既有条目
   delete : {"Name","Remoteip","Localip","Port","ID"}   ← 固件把 ip 写成小写，按原样发
   ```
   成功返回 `{}`；失败带非 0 `errcode`（如在防火墙关闭时 create 会得到 `9003`）。

5. **白名单条目结构**
   ```json
   {"Name":"NAS","RemoteIp":"::/0",
    "LocalIp":"240e:...:82c0","Port":16669,
    "ID":"InternetGatewayDevice.X_FireWall.Ipv6.Trustlist.1."}
   ```
   上限 **32 条**；`Port` 为 `-1` 表示全部端口。

6. **`/api/system/HostInfo`** 返回全网设备列表，每台含 `MACAddress`、`IPAddress`、
   `Ipv6Addrs[].Ipv6Addr`。**本程序的取址已经不用它了** —— 那是邻居表缓存，更新有延迟、
   还会留着设备已经不用了的旧地址。现在只留给控制台的「在线设备」页查 MAC。
   注意 `Ipv6Addrs` 常有两条以上（SLAAC 稳定地址 + RFC 4941 隐私临时地址），
   单数字段 `IPv6Address` 通常只是 `fe80::` 链路本地地址。

## 变更记录

### 1.0.8
- **总开关待机语义**：快捷操作新增 IPv6 防火墙滑动开关与「重置累计写入」；总开关关闭后
  同步暂停（旧行为是关着也照写，纯浪费 flash）、白名单卡收起为一行提示，重新打开后
  下一轮自动恢复同步并把地址追平。设了 `ENSURE_FIREWALL_ON=true` 时仍会自动打开开关。
- **状态胶囊适配多设备**：「采用地址」显示为「N 个 · M 台设备」，悬停逐台列出各设备
  本轮采用的地址或跳过原因；「累计写入」提示注明按条目计、含全部自动维护设备。
- **白名单管理重做（按设备维护）**：控制台「IPv6 防火墙白名单」卡升级为路由器同款
  表格（服务名称 / 允许来源 / 本地 IP / 通信端口 / 操作），点「＋ 添加条目」弹出
  设备选址窗：从设备列表选一台设备，自动填入它的当前地址（HostInfo 地址列表第一条，
  即路由器自己选设备时会填的那条），保存即写入白名单并加入**自动维护**——之后每轮
  同步跟随该设备地址变化原地更新。支持编辑（可换绑设备/改端口）与删除。
- **取址规则按规则绑定方式分流**：绑定了设备 MAC 的规则取路由器设备表第一条地址
  （华为排序=最新出现优先，第一条即现役地址）；设备离线、路由器表未重建（空表）时
  本轮跳过、白名单保持不动；规则指向本机时再用 `/proc/net/if_inet6` 的 flags 做
  幽灵校验（deprecated/tentative 已过滤，路由器残留的旧地址绝不写入）。未绑定 MAC
  的环境变量老规则仍读本机网卡，行为不变。
- **删掉「本机网卡 MAC」（TARGET_MAC）与「白名单条目」表单**：规则统一在白名单页
  按 device 管理（存 `settings.json` 的 `RULES`）；环境变量 `ENTRY_NAME` / `PORT` /
  `REMOTE_IP` / `TARGET_MAC` 仍兼容，读取时自动迁移成 RULES。「检测周期」并入
  「路由器连接」分组。
- **删除自动维护条目时连同规则一起删**，否则下一轮会被重新写回；手工条目的编辑/
  删除直接作用于路由器，程序不接管。
- 单测 **164 项**（新增 RULES 迁移与校验、设备规则离线/空表/幽灵地址跳过、改名清旧
  条目、删规则连删条目、白名单条目编辑/删除等用例）。
